## 2. 전체 파이프라인

```
[1] 제품 수집  ──▶ [2] USP 계산 ──▶ [3] 콘텐츠 생성 ──▶ [4] 영상 렌더
     (YOGO)          (가격/용량)        (훅·대본·캡션)       (v1/v2/v3)
                                                              │
[8] 다음 주 반영 ◀── [7] 성과 실측 ◀── [6] 예약 업로드 ◀── [5] 검수
     (승자 버전 확대)    (인사이트)         (스레드/인스타)     (오타·표기)
```

| 단계 | 입력 | 출력 | 현재 상태 |
|---|---|---|---|
| 1 제품 수집 | 오픈딜 링크 목록 | `data/products/_catalog.json` | Chrome에서 수동 → **스크래퍼 필요** |
| 2 USP 계산 | 가격·옵션·배송비 | 1개당/1알당/1포당 가격, 할인율, 무료배송 조건 | 수동 계산 → **함수화 필요** |
| 3 콘텐츠 생성 | 제품 데이터 | 제품 JSON(훅/계산/USP/퀴즈/이유/커버), 캡션, 스레드 글 | Claude가 작성 → **LLM 호출로 자동화** |
| 4 영상 렌더 | 제품 JSON | mp4 + 커버 이미지 | ✅ **코드 완성** (`video/`) |
| 5 검수 | 텍스트·영상 | 통과/수정 | 사람 눈 → **자동 체크 필요** |
| 6 예약 업로드 | mp4 + 캡션 + 일정 | 예약된 게시물 | Chrome에서 수동 클릭 → **자동화 필요** |
| 7 성과 실측 | 게시물 ID | 조회·저장·공유·프로필방문·링크클릭 | Chrome에서 수동 → **자동화 필요** |
| 8 반영 | 성과표 | 다음 주 버전 비중 | 사람 판단 → 규칙화 |

### 4-2. 버전별 장면 구성 (`render2.py`의 `PLANS`)

| 버전 | 장면 (초) | 훅 패턴 |
|---|---|---|
| v1 계산형 | cover 2.5 → math 4.0 → usp 5.0 → offer 3.5 | "1알 557원" 숫자 한 방 → 카운트업 계산 |
| v2 퀴즈형 | cover 2.5 → quiz_opts 3.0 → quiz_reveal 3.5 → usp 3.0 → offer 3.0 | "제일 싼 건?" → 3초 타이머 → 정답 도장 |
| v3 이유형 | cover 2.5 → reason0 3.0 → reason1 3.0 → reason2 3.0 → offer 3.5 | "딱 3초만 / 이 3개만" → 01·02·03 |

모든 버전 첫 프레임 = **커버(썸네일)**: 블러 배경 + 상단 질문 + 초대형 숫자 + 빨간 스티커 + 상품 카드. 프로필 그리드(3:4) 안전 영역 안에 핵심 요소 배치. `cover_3x4.jpg`도 함께 저장.

## 5. 단계별 구현 명세

### 5-1. 제품 수집 (YOGO 스크래퍼) — 신규

- 대상 URL: `https://yo-go.co.kr/product/detail.html?product_no={n}&sl={제휴토큰}`
  `sl`은 **제휴 추적 토큰**이라 링크 붙일 때 절대 지우면 안 됨.
- 수집 필드와 위치 (11/3 실측):

| 필드 | 위치 |
|---|---|
| 상품명 | 상단 `heading` (예: `[이남장] 설렁탕 550g_COSY 상시`) → `_COSY 상시` 접미사 제거 |
| 요약 USP | 상품명 아래 이모지 불릿 3줄 |
| 정가 / 판매가 / 할인율 | 상단 가격 영역 |
| 배송비 / 무료배송 조건 | "배송비 2,500원 (20,000원 이상 구매 시 무료)" |
| 옵션별 가격 | `select "구성 옵션"`의 option 텍스트 `(+21,900원)` 형태 → 기본가에 더해 계산 |
| 품절 여부 | 대표 이미지 위 `SOLD OUT` 오버레이 → **true면 제외** |
| 대표 이미지 | 상단 대표 `img` |

- ⚠️ 클라우드 작업 공간에서 `yo-go.co.kr` 직접 요청은 프록시에서 차단됐음 → **사용자 PC에서 Playwright로 실행**하거나 브라우저 경유.
- ⚠️ 상세 이미지(긴 상세페이지)는 "상세 이미지 더보기" 클릭 후 로딩, 렌더러가 멈추는 경우 있음 → 대표 정보만 우선 사용.

### 5-2. USP 계산 — 신규 (순수 함수)

```python
def unit_prices(options, shipping_fee, free_over):
    # options: [{"label":"60구","price":33400,"qty":60,"unit":"알"}, ...]
    # 반환: 1개당 가격, 배송비 포함 1개당 가격, 최저 단가 옵션, 1개 대비 절감액
```
- 계산식은 영상에 **그대로 노출**됨(예: `60구 33,400원 ÷ 60`). 반올림 규칙: 원 단위 정수, 나눠떨어지지 않으면 "약".
- 배송비가 있으면 "배송비 넣어도 한 개 N원" 문구 자동 생성.

### 5-3. 콘텐츠 생성 — LLM 호출로 자동화

입력: 제품 수집 결과 + 계산 결과 + 이번 주 레퍼런스.
출력: 4-1 제품 JSON 전체 + 인스타 캡션 3개 + 스레드 본문/링크칸 3세트.

프롬프트에 넣을 규칙:
1. 수치·인증·효능은 **수집 데이터에 있는 것만**. 없는 건 쓰지 않는다.
2. 1인칭 사용 후기 표현 금지("2주 써봤어요" ×). 스펙 비교 톤.
3. 첫 줄 `[광고]`.
4. 커버 `big`은 7자 이내 숫자/질문, `top`은 15자 이내.
5. 스레드 본문은 공감 질문형, 제품명·링크는 2번째 칸.
6. 인스타 캡션 끝 고정: `🔖 저장해두고 … 꺼내보세요` / `🔗 구매 링크는 프로필에` / 해시태그 5~7개(마지막 `#사기전에`).
7. 레퍼런스는 최근 1개월 잘 터진 것의 **구조·훅 패턴만** 빌리고 문구는 새로 쓴다.

### 5-4. 영상 렌더 — ✅ 완성 (`video/`)

```bash
pip install pillow numpy --break-system-packages   # ffmpeg, Noto Sans CJK 폰트 필요
python3 video/render2.py data/products/egg.json v2 out/egg_v2          # 영상(무음)
python3 video/render2.py data/products/egg.json v2 out/egg_v2 stills   # 검수용 정지 컷만
python3 video/audio.py out/egg_v2/bgm.wav out/egg_v2/plan.json         # 장면에 맞춘 효과음
bash video/build_all.sh                                                 # 전체 일괄
```

- 장면별로 따로 인코딩 후 `concat -c copy`, 오디오는 `-c:v copy`로 합침(재인코딩 없음).
- 폰트: `/usr/share/fonts/opentype/noto/NotoSansCJK-{Black,Bold,Medium}.ttc` index 1(KR). Windows면 경로를 바꿔야 함(`render.py` 상단 FB/FD/FM).
- 이미지 크롭 하단 26px은 캡처 잔여 테두리 제거용.

### 5-5. 검수 — 신규 (자동 체크리스트)

| 체크 | 방법 |
|---|---|
| 첫 줄 `[광고]` | 문자열 검사 |
| 금지어 | "써봤", "효과 보장", "100%", "완치" 등 리스트 |
| 숫자 일치 | 영상/캡션의 가격이 수집 데이터와 같은지 |
| 오타 | 입력한 텍스트와 화면에 들어간 텍스트 **재대조** (11/3 실제 사고: 유니코드 한 글자 실수로 "바꿨어요"→"바꿈어요"가 들어감 → 게시 전 화면 텍스트 재확인으로 잡음) |
| 품절 재확인 | 게시 직전 상품 페이지 SOLD OUT 체크 |
| 영상 | 길이 15.0초, 1080×1920, 오디오 트랙 존재, 첫 프레임 커버 |

### 5-6. 예약 업로드 — 신규 (가장 중요)

두 가지 구현 방법이 있음:

**방법 A. 공식 API (권장, 안정적) [업데이트 필요: 착수 전 최신 문서 확인]**
- 인스타: Instagram Graph API 콘텐츠 게시(REELS). 프로페셔널 계정 + 페이스북 페이지 연결 + Meta 앱 등록 필요. 예약 기능은 API에 따라 다를 수 있어 **자체 스케줄러(cron)로 정시에 게시**하는 구조 권장.
- 스레드: Threads API 게시. 텍스트+영상 게시 후 `reply_to_id`로 2번째 칸(링크) 게시. 마찬가지로 자체 스케줄러.

**방법 B. 브라우저 자동화 (Playwright, 지금 손으로 한 절차 그대로)**
- 사용자 PC에서 로그인된 크롬 프로필로 실행(로그인·2단계 인증은 사람이 1회).
- 아래는 11/3 실제로 성공한 클릭 순서와 함정.

**스레드 예약 (threads.com 웹)**
1. 홈 상단 "새로운 소식을 공유해보세요" 클릭 → 작성창
2. 작성창 안 `input[type=file]`에 mp4 첨부 (작성창이 열려야 DOM에 생김)
3. 본문 입력 → "스레드에 추가" 버튼 → 2번째 칸에 `[광고] … 링크`
4. 우상단 `…` → "예약..." → **⚠️ 첫 클릭은 자주 무시됨. 달력이 뜰 때까지 재클릭**
5. 달력에서 날짜 클릭, `hh`/`mm` 텍스트박스에 24시간제 입력 → "완료"

  A='ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_'
